# Publishing through Vercel

On 16 November 2026 Anton said this site can be published the regular way,
through Vercel. The static export is deployed there, and since 21:25 UTC that
day `beyondyourvaluation.com` resolves to it. The earlier Sites project was
left as it was and no longer receives the domain's traffic.

## What exists

- Vercel project `beyond-your-valuation` (`prj_V636LgGmygKHd5UlO2QvNRO9Oi5s`),
  no framework, no build step, zero functions and no scheduled jobs.
- Production deployment `dpl_` recorded in the Worth Building repository at
  `lab/releases/2026-11-16-beyond-vercel/deployment.json`: the 33 files of
  `out/` plus `vercel.json`. Deployed file hashes match the local build.
- Addresses: https://beyondyourvaluation.com/ and, as the project's default,
  https://beyond-your-valuation.vercel.app/
- `www.beyondyourvaluation.com` redirects to the apex with status 308, keeping
  the path and query.

`vercel.json` sets trailing-slash routes to match the export, six security
headers including a content security policy, and long caching for the
content-hashed files under `/_next/static/`. The earlier hosting sent none of
those headers.

## To publish a later change

```sh
npm ci && npm test && npm run typecheck && npm run build
rm -rf /tmp/beyond-deploy && cp -r out /tmp/beyond-deploy && cp vercel.json /tmp/beyond-deploy/
mkdir -p /tmp/beyond-deploy/.vercel
printf '{"projectId":"prj_V636LgGmygKHd5UlO2QvNRO9Oi5s","orgId":"team_Zqc3E0ijRQT1oANV2ZMaS79w"}' > /tmp/beyond-deploy/.vercel/project.json
cd /tmp/beyond-deploy && vercel deploy --local-config vercel.json --prod --yes
```

Run the two browser suites against the result with `BASE_URL` set to the
deployed address.

## The domain

Two web records were changed at the registrar, and nothing else:

| Type | Host | Before | Now |
| --- | --- | --- | --- |
| A | @ | the two Sites addresses | 216.198.79.1 and 64.29.17.1 |
| CNAME | www | custom-domains.chatgpt.site | the project's `vercel-dns-017.com` name |

The nameservers, the mail forwarding mode and the four Sites verification TXT
records are unchanged, so going back to Sites would mean restoring those two
rows. The zone before and after the change is saved privately outside both
repositories. Vercel issued the certificates about a minute after the records
were published.

## Verification on 16 November 2026

- All 19 model tests, the type check and the build pass.
- Both browser suites pass in Chromium and WebKit at 1440 and 390 pixels:
  locally, locally with the new headers, and against the public Vercel
  address.
- Six sampled public files are byte-identical to the local build. The
  security headers, the immutable cache header on a hashed asset and the
  trailing-slash redirect were checked on the public address.
- After the DNS change, four public resolvers and both registrar nameservers
  returned the new records. The apex answered 200 over ordinary HTTPS with
  bytes identical to the local build, and www answered 308 to the apex.
- Both browser suites and the hero-position check were then run against
  `https://beyondyourvaluation.com` itself and passed in Chromium and WebKit.
